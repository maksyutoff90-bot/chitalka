# Россия: чек-лист перед продажей

Обновлено: 2026-11-07. Не юридическая консультация.

## 1. Кто продаёт

- [ ] выбрать форму: самозанятый, ИП или ООО;
- [ ] проверить, подходит ли выбранный режим для продажи ПО;
- [ ] получить ИНН/ОГРН/ОГРНИП;
- [ ] добавить реквизиты в EULA и Privacy;
- [ ] указать email для претензий и обращений по персональным данным;
- [ ] проверить налоговый режим и необходимость чеков по 54-ФЗ.

Сейчас в документах указано физическое лицо — владелец проекта. Для регулярной
продажи этого недостаточно.

## 2. EULA и потребители

Применимы:

- Закон РФ от 07.02.1992 № 2300-1 «О защите прав потребителей»;
- Гражданский кодекс РФ (лицензионный договор, ст. 1286 и др.);
- правила площадки продажи.

Проверить:

- [ ] акцепт EULA через чекбокс и кнопку;
- [ ] право потребителя отказаться от исполнения договора (ст. 32);
- [ ] правила возврата цифрового товара и дистанционной покупки (ст. 26.1);
- [ ] подсудность: потребитель — по своему месту жительства/пребывания
  (ст. 17); юрлица — по месту нахождения правообладателя;
- [ ] ограничение ответственности не ущемляет права потребителя;
- [ ] срок поддержки и обновлений;
- [ ] порядок изменения EULA.

Спорный вопрос: считается ли возврат ПО после предоставления доступа
ограниченным. Это нужно проверить у юриста, а не решать формулировкой в EULA.

## 3. Персональные данные (152-ФЗ)

Проверить:

- [ ] является ли владелец оператором персональных данных;
- [ ] нужно ли уведомление Роскомнадзора (ст. 22);
- [ ] локализация основной базы данных в РФ (ст. 18(5));
- [ ] правовые основания обработки;
- [ ] согласие на онлайн-передачу выделенного текста;
- [ ] трансграничная передача в GitHub/DeepL/Wikimedia (ст. 12);
- [ ] сроки хранения логов и кэша;
- [ ] порядок ответа на обращения субъектов (ст. 14, 20);
- [ ] удаление данных;
- [ ] детские данные;
- [ ] договоры поручения с подрядчиками, если появятся.

Сейчас приложение хранит данные локально и не имеет серверной телеметрии.
Но GitHub Issues, DeepL и другие сервисы могут получать данные пользователя.

## 4. Платежи и оферта

- [ ] цена и валюта;
- [ ] оферта или EULA на странице покупки;
- [ ] оплата и чек;
- [ ] возврат;
- [ ] лицензионный ключ/доступ;
- [ ] поддержка;
- [ ] правила акций и скидок;
- [ ] налоги.

## 5. Публичный GitHub

- [ ] репозиторий публичный — не считать его «закрытым исходным кодом»;
- [ ] добавить LICENSE для кода, если планируется открытая лицензия;
- [ ] не публиковать ключи, email и персональные данные;
- [ ] Issues — публичный канал; предупредить пользователей;
- [ ] не обещать конфиденциальность публичных Issues.

## 6. FreeDict

- [ ] база отдельным файлом;
- [ ] CC BY-SA 3.0 и атрибуция;
- [ ] отметка изменений;
- [ ] без DRM;
- [ ] проверить database rights;
- [ ] получить заключение юриста.

## 8. Вопросы юристу

1. Достаточно ли текущего акцепта EULA?
2. Как правильно оформить возврат цифрового ПО по ст. 32 и 26.1?
3. Можно ли ограничить ответственность в текущей редакции?
4. Нужно ли уведомление РКН при текущей архитектуре?
5. Нужно ли согласие на DeepL/Викисловарь?
6. Как оформить трансграничную передачу?
7. Достаточно ли отдельного SQLite для FreeDict?
8. Можно ли продавать как самозанятый/ИП?
9. Какие чеки и документы нужны?
10. Какие риски публичного GitHub?

## Минимум перед продажей

1. ИП/ООО или самозанятость.
2. Email для претензий.
3. Проверка EULA/Privacy юристом.
4. Проверка 152-ФЗ и РКН.
5. Правила возврата.
6. Сертификат и подпись exe.
