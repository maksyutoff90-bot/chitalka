# Пакет для юридической проверки

**Статус: не проверено юристом.** Этот файл — задание для юриста, а не
заключение. Дата: 2026-11-07.

## Что нужно проверить

1. EULA: применимость, принятие, возврат, ответственность, подсудность.
2. Политику конфиденциальности: правовые основания, передачи, права субъектов.
3. FreeDict/CC BY-SA: adaptation vs collection, share-alike, атрибуция,
   database rights, совместимость с закрытым коммерческим приложением.

## Факты о продукте

- Название: «Читалка».
- Версия: 1.0.0.
- Платформа: Windows, portable exe.
- Юрисдикция: **Российская Федерация**.
- Форматы: FB2, FB2.ZIP, EPUB, PDF, TXT.
- Распространение: GitHub / portable-zip; планируется платная версия.
- Текущая версия: бесплатная.
- Данные: библиотека, настройки, заметки, статистика и кэш хранятся локально.
- Телеметрии нет.
- Онлайн-функции: OPDS, Gutenberg, Викитека, Викисловарь, DeepL,
  LibreTranslate, MyMemory (по выбору пользователя), проверка GitHub Releases.
- PDF: PDFium/pypdfium2 (BSD/Apache), PyMuPDF не используется.
- Словарь: FreeDict/WikDict, CC BY-SA 3.0, отдельный SQLite-файл.
- Код приложения: проприетарный; репозиторий публичный.
- Платная модель: пока не запущена.

## Чего не хватает для заключения

- [ ] юридическое лицо/ИП, ИНН;
- [ ] форма: самозанятый, ИП или ООО;
- [ ] email для претензий и персональных данных;
- [ ] цена платной версии;
- [ ] правила возврата и площадка продажи;
- [ ] срок поддержки;
- [ ] планируемые страны продажи (РФ и/или ЕС);
- [ ] есть ли обработка данных детей;
- [ ] нужен ли договор с пользователем-юрлицом.

## Вопросы юристу

### EULA

1. Достаточно ли чекбокса и кнопки «Принять» для акцепта EULA?
2. Нужна ли отдельная подпись/оферта для платной версии?
3. Законно ли ограничение ответственности в текущей формулировке?
4. Как правильно оформить возврат для цифрового товара в выбранной
   юрисдикции?
5. Можно ли указать подсудность по месту правообладателя, если пользователь —
   потребитель?
6. Нужны ли отдельные условия для ЕС/Великобритании/России?
7. Достаточно ли ссылки на EULA внутри приложения?
8. Как уведомлять об изменениях EULA?
9. Можно ли использовать «владелец проекта» вместо ИП/ООО до регистрации?
10. Какие формулировки о проприетарности безопасны, если репозиторий публичный?

### Privacy

1. Кто является оператором/контроллером данных?
2. Какие правовые основания для локальной библиотеки, кэша и логов?
3. Нужно ли согласие на отправку выделенного текста в DeepL/Викисловарь?
4. Как описать международную передачу в GitHub/DeepL?
5. Достаточно ли раздела о правах субъекта данных?
6. Какие сроки хранения указать для логов и кэша?
7. Нужен ли DPA с DeepL/LibreTranslate?
8. Нужно ли упоминать GitHub Issues как публичный канал?
9. Нужна ли отдельная политика cookie, если их нет?
10. Какие требования к согласию несовершеннолетних?

### FreeDict

1. Является ли StarDict → SQLite адаптацией или коллекцией?
2. Распространяется ли share-alike на код приложения?
3. Достаточно ли отдельного `.xz`-файла и отсутствия DRM?
4. Какая атрибуция обязательна: авторы, название, URI, изменения?
5. Нужно ли публиковать сборщик и исходные StarDict-архивы?
6. Действуют ли sui generis database rights в стране продажи?
7. Можно ли продавать приложение, если база бесплатна и отделяема?
8. Нужно ли предлагать базу отдельно для скачивания?
9. Какие формулировки в EULA не должны ограничивать CC BY-SA?
10. Нужно ли получать разрешение FreeDict дополнительно?

### Россия

1. Достаточно ли акцепта EULA по ст. 435/438 ГК РФ?
2. Как применить ст. 32 и 26.1 Закона № 2300-1 к цифровому ПО?
3. Можно ли ограничить ответственность без ущемления прав потребителя?
4. Нужно ли уведомление Роскомнадзора по ст. 22 152-ФЗ?
5. Нужна ли локализация по ст. 18(5) 152-ФЗ?
6. Как оформить трансграничную передачу по ст. 12 152-ФЗ?
7. Нужно ли согласие на отправку текста в DeepL/Викисловарь?
8. Можно ли продавать как самозанятый/ИП и какие чеки нужны?
9. Как указать подсудность, не нарушая ст. 17 Закона № 2300-1?
10. Какие риски у публичного GitHub и GitHub Issues?
